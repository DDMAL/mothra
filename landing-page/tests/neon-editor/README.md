These integration tests mount the production `NeonBatchEditor` React component
and load the real iframe assets built into `public/neon`. Cypress supplies only
the local Mothra API responses and a blank manuscript image. PUT requests contain
the MEI serialized by Neon; subsequent GET requests return that saved content.
The initial React props deliberately retain the old XML, matching cached project
metadata and detecting accidental replay over a saved notation change.
The correction callback updates the file array as AppRouter does. Authentication,
Postgres persistence, and the rest of AppRouter are not exercised by this fixture.
The assertions cover successful saves with an OK response; they do not establish
behavior for failed saves, timeouts, or Neon's local fallback.

Use Node 22 and the repository's installed dependencies. From `landing-page`,
build the pinned Neon and Mothra assets before starting the test server:

```sh
npm run build
node node_modules/vite/bin/vite.js --config tests/neon-editor/vite.config.ts
```

In another terminal, also from `landing-page`:

```sh
node neon/node_modules/cypress/bin/cypress run --project . --config-file tests/neon-editor/cypress.config.cjs
```

This configuration has no backend proxy and needs no live API or credentials.
The built Neon HTML may still load
its normal public CDN libraries. Manifest identities are unique per test, while
navigation inside a test keeps the same identities to exercise real settings
and document lifecycle behavior. A new edit-session POST gets a new identity,
matching the actual Mothra API.

Neon's development webpack configuration caches compiled modules. After changing
the Neon commit or its source, clear `neon/node_modules/.cache/hard-source` before
building if the output retains the old version label. The version in the built
editor should match `git -C neon rev-parse --short HEAD`.

## Coverage

The original six tests exercise:

- Initial Square/Hufnagel selection and navigation without creating edits.
- Both notation-conversion directions through Neon's actual Save control, with
  assertions on the raw MEI PUT and navigation back to the edited page.
- A fresh edit session after each saved conversion. The test verifies a new
  session identity, a new content GET, and XML matching the saved PUT, despite
  React props retaining the old XML.
- Canceling or confirming the unsaved-navigation dialog without writing to the
  content API. This does not verify full data consistency after discarding edits.
- Mark Done after conversion, with an assertion that the successful MEI PUT
  response has completed before corrected PATCH is sent.
- Native Hufnagel connection editing, Mark Done, and reopening the saved MEI.

Both specs observe the real Verovio worker to wait for initial font loading and
rendering before interactions. The conversion tests also check the MEI passed to
the renderer. The shared observer does not replace the renderer or change its inputs.

The native-connection test uses MEI generated by Mothra `7ac370a` for Hufnagel
clivis2a. It checks connector glyphs, unlink/relink, then saves an unlinked state
(different from the original) with Mark Done and reopens it from the content API.
It also checks PUT-response completion before corrected PATCH.

Seven additional tests in `embedded-handles.cy.js` adapt #1410's samples and
gestures to the real Mothra iframe: Square/Hufnagel CSS-pixel sizing through Neon
Zoom, slider use with text bboxes hidden, MEI invariance under UI changes, legal
content drags with off-image handles (including a ten-times-smaller surface), and
glyph/staff-line out-of-image rejection with restored MEI. Measurements are
written to `artifacts/handle-results.json`; the final suite has 13 tests.

The pinned Neon is based on official develop `7f632275`, including merged #1410,
plus the cache dirty-state fix from `2a46faaf` / previous delivery `1b6e34ab`. See
`documentation_allons-y/NEON_215_VERIFICATION.md` at the repository root for the
exact pin, validation results, asset comparison, and publication order. The suite
does not depend on any files or absolute paths in a personal workspace.

To run only the ordinary connection-editing path:

```sh
node neon/node_modules/cypress/bin/cypress run --project . --config-file tests/neon-editor/cypress.config.cjs --spec tests/neon-editor/native-connections.cy.js
```
