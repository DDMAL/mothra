# Evaluation Aligned with v1 Baseline

## Background

The v1 YOLOv8 model (`models/v1/yolov8m_17images_7568boxes.pt`, trained on 17 images)
reported **per-class mAP@50**:

| class  | mAP@50 |
|--------|--------|
| text   | 0.77   |
| music  | 0.67   |
| staves | —      |

All grid search and Optuna experiments in `trainingscript_wy` reported **mAP@50-95** instead,
which is a stricter metric (averages over IoU thresholds 0.50–0.95) and is not directly
comparable to v1's numbers.

`scripts_v11/eval_v1_aligned.py` fixes this by reporting per-class mAP@50 alongside
mAP@50-95, and by producing the same inference output format as the `inference-outputs`
branch (`_predicted.jpg` + mothra-annotator-compatible `.json`).

---

## Script: `scripts_v11/eval_v1_aligned.py`

Two modes, usable independently or together:

| Mode    | What it does |
|---------|-------------|
| `eval`  | Runs `model.val()` on a labelled split; prints and saves per-class mAP@50 |
| `infer` | Batch inference; writes `_predicted.jpg` + `.json` per image |
| `both`  | Runs eval then infer in one call (default) |

Output of **infer** mode mirrors `inference-outputs` branch exactly:
```
<out-dir>/
    <stem>/
        <stem>_predicted.jpg
        <stem>.json             ← mothra-annotator schema, loadable into annotator
    all_predictions.json        ← aggregated
```

Output of **eval** mode:
```
<out-dir>/
    eval_summary.csv            ← per-class mAP@50, mAP@50-95, P, R
```

## Commands

All commands should be run from the **repo root** (`mothra/`).

### 1. Eval only — compare a v11 checkpoint against v1 metrics

```bash
python scripts_v11/eval_v1_aligned.py \
    --mode eval \
    --weights outputs/yolo11/runs/detect/weights/best.pt \
    --data outputs/yolo11/datasets/data.yaml \
    --split test \
    --out-dir models/eval_v1_aligned
```

> **Note:** `data.yaml` is generated by the training script under
> `<output_root>/datasets/data.yaml`. Use `--split val` if no test split was created
> (small dataset).

### 2. Infer only — visualise predictions on holdout pages

```bash
python scripts_v11/eval_v1_aligned.py \
    --mode infer \
    --weights outputs/yolo11/runs/detect/weights/best.pt \
    --source data/holdout \
    --out-dir models/predictions_v11_aligned
```

### 3. Both at once

```bash
python scripts_v11/eval_v1_aligned.py \
    --mode both \
    --weights outputs/yolo11/runs/detect/weights/best.pt \
    --data outputs/yolo11/datasets/data.yaml \
    --source data/holdout \
    --out-dir models/eval_v1_aligned
```

### 4. Use a config YAML to inherit imgsz / device / thresholds

```bash
python scripts_v11/eval_v1_aligned.py \
    --mode both \
    --weights outputs/yolo11/runs/detect/weights/best.pt \
    --config configs/mothra_base11.yaml \
    --data outputs/yolo11/datasets/data.yaml \
    --source data/holdout \
    --out-dir models/eval_v1_aligned
```

### 5. Evaluate the original v1 YOLOv8 model (for a direct comparison run)

```bash
python scripts_v11/eval_v1_aligned.py \
    --mode infer \
    --weights models/v1/yolov8m_17images_7568boxes.pt \
    --source data/holdout \
    --out-dir models/predictions_v1_rerun \
    --imgsz 640
```

> This re-runs inference with the original v1 weights using the same script,
> so the output format is identical and images can be compared side-by-side.

---

## Key flags

| Flag | Default | Notes |
|------|---------|-------|
| `--weights` | required | Path to `.pt` checkpoint |
| `--data` | required (eval) | `data.yaml` generated by training script |
| `--source` | required (infer) | Directory of images to run inference on |
| `--split` | `test` | Which split to evaluate: `train`, `val`, `test` |
| `--conf` | `0.25` | Confidence threshold — matches v1 default |
| `--iou` | `0.7` | IoU threshold — matches v1 default |
| `--imgsz` | `640` (or from config) | Inference resolution |
| `--device` | `0` (or from config) | GPU index or `cpu` |
| `--out-dir` | `models/eval_v1_aligned` | Where outputs are written |
| `--line-width` | `2` | Bbox line thickness in overlay images |
| `--font-size` | `14.0` | Label font size (fixed to avoid huge text on large pages) |

## Grid Search: `scripts_v11/eval_grid_v1_aligned.py`

The grid search results CSV (`models/results_multi_metrics_best_per_metric.csv`) already
records overall mAP@50 per run, but **not per-class mAP@50**.  This script re-evaluates
all `status=ok` checkpoints that are present on disk and adds the per-class breakdown.

Because there are up to 74 ok runs, inference visualisation is intentionally limited to
the **top N** checkpoints (default 3, ranked by overall mAP@50).

Output layout:
```
<out-dir>/
    grid_eval_v1_aligned.csv          all-runs per-class mAP@50 summary
    top3/
        01_<best-tag>/
            <stem>_predicted.jpg
            <stem>.json               mothra-annotator format
            all_predictions.json
        02_<second-tag>/  ...
        03_<third-tag>/   ...
```

### Commands

```bash
# Full run: evaluate all checkpoints + visualise top 3
python scripts_v11/eval_grid_v1_aligned.py \
    --data-yaml models/grid_search_v11_aug/data_yaml_path.txt \
    --source    data/holdout \
    --out-dir   models/grid_eval_v1_aligned \
    --top-n     3

# Evaluate only, no inference
python scripts_v11/eval_grid_v1_aligned.py \
    --data-yaml models/grid_search_v11_aug/data_yaml_path.txt \
    --out-dir   models/grid_eval_v1_aligned \
    --top-n     0

# Dry run — check which checkpoints are present without touching GPU
python scripts_v11/eval_grid_v1_aligned.py \
    --data-yaml models/grid_search_v11_aug/data_yaml_path.txt \
    --dry-run

# Use val split instead of test (for small datasets)
python scripts_v11/eval_grid_v1_aligned.py \
    --data-yaml models/grid_search_v11_aug/data_yaml_path.txt \
    --source    data/holdout \
    --split     val \
    --top-n     5
```

> **Note:** `data_yaml_path.txt` is written by `grid_search_v11_aug.py` and contains
> the path to the fixed dataset split's `data.yaml`.  If checkpoints are stored on a
> different machine or under a different base path, the `best_pt` column in the results
> CSV needs to be accessible (e.g. via symlink or by copying checkpoints locally).
